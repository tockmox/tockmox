# ai-node

The toolkit that makes an Apple-silicon Mac an inference node that converges
itself from a site repository. The operator's guide is
[AI nodes](../docs/administration/ai-nodes.md); this file is the map of the
directory and the commands for working on it. Experimental, macOS only.

## What is here

| Path | Is |
|---|---|
| `bootstrap-node.sh` | The first step on a new Mac: accounts, Homebrew, keys, pins, first converge. Bash 3.2, run as the human administrator |
| `bin/tockmox-ai-node-converge` | The converger: fetch, verify signatures, decrypt, load, run; writes `converge.prom` and `state.json` |
| `bin/tockmox-ai-node-facts` | The unprivileged readiness writer, run by launchd as the service account |
| `bin/tockmox-ai-node-engine-watch` | Restarts an engine that is up but answers 503 on its health path (mlx-lm: generation thread died), every 60 s as root; writes `engine-watch.prom` |
| `playbooks/ai-node.yml` | The one playbook; `playbooks/filter_plugins/` holds its Python filters |
| `roles/` | One role per concern; `launchd_service` is the helper the others call |
| `schema/` | JSON Schemas for `ai-node.yaml` and `desired.yaml` (written by the renderer) |
| `examples/` | A generic site slice to copy: `fleet.yaml`, signers, a node's two files, encrypted secrets |
| `tests/` | Unit tests, the converger and bootstrap tests, and the Linux simulation |

## Contract with the rest of Tockmox

- `desired.yaml` is generated by the renderer in `tockmox-ui`; the toolkit only
  reads it. `ai-node.yaml` is authored. Both are validated against `schema/`.
- Ports are read from the files, never defaulted: the exporter ports must equal
  the `metrics` ports on the inference node, and the engine ports the endpoints.
- The converge writes `tockmox_ai_node_converge_*` series and the facts writer
  `tockmox_ai_node_*` series to `/opt/tockmox/textfile`; node_exporter serves them.
- Labels are `<prefix>.<service>` with the prefix from `ai-node.yaml`
  (`com.tockmox.ai-node` by default). An instance whose id already starts with its
  engine name keeps it (`...mlx-lm-8080`); any other id is prefixed
  (`...mlx-lm-eval`). Ollama is `<prefix>.ollama`.

## Checks

```bash
tools/check-ai-node.sh
tools/check-ai-node.sh --selftest
```

The first lints everything (`shellcheck`, `yamllint`, `ansible-lint` at the
production profile, `--syntax-check`, a bash-3.2 and BSD-userland scan) and runs
the Python unit tests, the converger tests against a real signed git repository,
and the bootstrap tests against fakes of the macOS tools. It needs no Mac and no
network. The second proves the scan can go red.

The Linux simulation runs the whole playbook twice against stand-ins for the
macOS commands. It needs root, creates empty directories such as `/Library` and
mounts tmpfs and overlays in a private mount namespace, and takes about five
minutes, so it is opt in:

```bash
sudo tools/check-ai-node.sh --e2e
```

What none of this proves is anything about macOS itself. The list of what waits
for a Mac, with the command that settles each item, is under
[what is not certified here](../docs/administration/ai-nodes.md#what-is-not-certified-here).

## Working on it

- A role that runs only on macOS has `tasks/main.yml` that stops on Linux with
  `tn_linux_message` and `tasks/macos.yml` that does the work. Keep that split;
  the Linux branch is where phase 6 goes.
- Every command that changes state is read first, so a second run reports no
  change. The simulation asserts it.
- Nothing in a script prints a secret. The age and deploy keys are generated on
  the node and only their public halves leave it.
- No site-specific names, addresses or domains. Use `example.com` and the
  documentation address ranges.
- A change to a script that runs on the Mac must stay bash 3.2: no associative
  arrays, `mapfile`, `${var,,}`, `|&`. `tools/check-ai-node.sh` fails on them.
