# THE KURED REBOOT GATE: one decision per alert Tockmox authors.
#
# kured can hold a node reboot while named alerts fire. It holds only for the
# alerts a site lists in kured.configuration.alertFilterRegexp (with
# alertFilterMatchOnly: true), so an alert nobody listed never holds a reboot,
# and nothing errors. The old failure was loud (every alert blocked, patching
# stopped); the inclusion list fails quietly. This file is what makes the quiet
# direction loud: tools/check-kured-gate.sh fails when a Tockmox alert has no
# line here, when a line names an alert that no longer renders, when an upstream
# alert the gate names has been renamed, and when the regexp printed in
# docs/operations/monitoring.md is not the one this file implies.
#
# FORMAT, one entry per line, a reason after the # is required:
#
#   alert NAME block  # a firing NAME means: do not take another node down now
#   alert NAME pass   # NAME does not change whether a reboot is safe
#   upstream NAME     # an alert a subchart ships that the gate names; it must still render
#
# Rules of thumb used below. block: the alert says the cluster has lost
# redundancy, quorum or capacity that a drain would spend. pass: the alert is
# about delivery, backups, certificates, tooling or a service a reboot does not
# worsen. These are decisions, not facts; a site that disagrees overrides
# alertFilterRegexp in its own values. The alternative to a line here is an
# annotation on the rule, `kured_gate: block|pass` (an annotation name cannot
# contain a dot or a slash); a rule must be classified in one place, not both.
#
# Alerts the gate cannot see: a site's own rules are not in this file. A site
# that wants the same guarantee runs the same kind of check over its own rules.

# ---- platform: storage and databases ----
alert TockmoxLonghornVolumeFaulted        block  # no healthy replica; a drain can remove the last copy a rebuild needs
alert TockmoxLonghornVolumeStuckAttaching block  # a volume cannot attach; a drain moves more workloads onto the same fault
alert TockmoxLonghornVolumeDegraded       block  # fewer healthy replicas than configured for 30 minutes and not rebuilding; the next node may hold the survivor
alert TockmoxLonghornStorageFull          block  # past the point where replicas stop scheduling; an evicted replica has nowhere to rebuild
alert TockmoxCNPGClusterNotHealthy        block  # the operator cannot see or manage an instance; failover state is unknown while a node drains
alert TockmoxCNPGInstancesNotReady      block  # fewer ready instances than wanted; draining the node that holds the survivor takes the database down
alert TockmoxCNPGScrapeTargetAbsent       pass   # database metrics are not collected; a blind spot, and a reboot does not change it
alert TockmoxPersistentVolumeClaimPending pass   # a claim nothing provisioned; a reboot does not make it better or worse
alert TockmoxCNPGBackupUnhealthy          pass   # backups are failing; availability is unchanged by a reboot
alert TockmoxCertificateNotReady          pass   # certificate issuance; unrelated to node availability
alert TockmoxCertificateExpiringSoon      pass   # renewal is failing; unrelated to node availability

# ---- platform: self-checks ----
alert TockmoxSelfCheckStale               pass   # the heartbeat is stale; kured already fails closed when Prometheus cannot answer
alert TockmoxTargetsDown                  pass   # scrape targets down; a drain is not what fixes or worsens them
alert TockmoxPersistentVolumeFillingUp    pass   # a volume is filling; a reboot does not change the rate

# ---- ai layer ----

alert TockmoxAiNodeSignatureUnverified    pass   # same
alert TockmoxAiNodeEngineRestarting       pass   # same: an engine restart on a Mac, not a cluster node
alert TockmoxWalArchiveBacklog            pass   # archiving is behind; availability is unchanged by a reboot
alert TockmoxRestoreDrillStale            pass   # the drill is overdue
alert TockmoxRestoreDrillNeverRan         pass   # the drill has not run
alert TockmoxRestoreDrillFailed           pass   # the drill failed
alert TockmoxUISignInFailing              pass   # the console sign-in; a service fault, not node safety
alert TockmoxUIUnreachable                pass   # the console is down; a service fault, not node safety

alert TockmoxAuthentikBackupNeverRan      pass   # a backup has not run

alert TockmoxLokiNotIngesting             pass   # logs are not arriving; a reboot does not change it, and the pipeline alert is deliberately blind to pods
alert TockmoxLokiIngestionCollapsed       pass   # a shipper stopped on some node; a reboot does not make logs arrive
