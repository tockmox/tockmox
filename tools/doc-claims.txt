# COUNTABLE CLAIMS THE DOCUMENTATION MAKES ABOUT THIS TREE.
#
# Read tools/check-doc-claims.sh first; it explains why this file exists. The
# short version: everything GENERATED here is checked and prose is not, and the
# prose that states real numbers is the highest-value prose on the site because
# the project's credibility rests on it. `docs/administration/configuration.md`
# asserted four countable things at once and all four had stopped being true.
#
# FORMAT. Blocks separated by blank lines, any key order:
#
#   page:   path from the repo root. Must exist.
#   claim:  literal text that must still appear on that page. NOT a regex.
#   test:   a shell command, run from the repo root. Its stdout is trimmed.
#   expect: what that command must print.
#   states: OPTIONAL regex. Every match on the page has its FIRST TOKEN read as
#           a number, and each one must equal `expect`. Number words count up
#           to twenty; above that, write digits (house style does anyway).
#
# THREE ways to fail, and each catches a different lie.
#
#   test != expect   the TREE changed and the page is now wrong.
#   claim not found  THIS FILE is wrong -- somebody rewrote the sentence and the
#                    assertion outlived it, still passing, guarding nothing. An
#                    assertion registry that can rot silently is worse than none,
#                    because it is believed.
#   states mismatch  the page states a number the tree contradicts. This is the
#                    one that catches an edit to the sentence itself, and it
#                    exists because the first version of this gate did NOT have
#                    it and passed its own poison test -- see the note in
#                    check-doc-claims.sh. Add `states` to every entry whose
#                    claim contains a count.
#
#   class mismatch    ANY page in scope states a number for a kind of thing the
#                    tree can count, and it is wrong. This is the one that does
#                    not depend on somebody having registered the sentence; see
#                    the CLASSES section at the bottom. Added 2026-09-04 after
#                    three contradictions sat green because none was listed.
#
# WHAT BELONGS HERE. A sentence a reader would quote back at us, whose truth a
# command can decide. "Nine layers" belongs. "Fast" does not. "Ships Harbor"
# belongs, because `Chart.yaml` settles it. If the same noun is counted on more
# than one page, make it a `class:` rather than a second `page:` entry.
#
# WHAT DOES NOT BELONG HERE YET, and it is deliberate: claims that need a helm
# render of ALL NINE charts to settle, such as `what-you-get.md`'s "528
# rendered resources" and `airgap.md`'s "59 of 59 pods". They are real claims of
# exactly this class and they are the ones most likely to drift.
#
# THEY DID DRIFT, and the sentence above predicted it: on 2026-09-12, reading
# the release preflight's WARN list by hand turned up 526 where the tree renders
# 528, and an observability row reading 156 where it renders 158. Nobody had
# mis-edited anything; the numbers simply moved and nothing re-measured them.
# Fixed by hand, which is the fix that will be needed again at the next release.
# A one-chart render is now paid for three times over (see the NetworkPolicy
# entries); a nine-chart one is a different order of cost and still waits on the
# artifact. They are not here because CI already
# renders 27 times in a job that owns the chart machinery, and paying for a
# 28th render inside a docs check is the wrong place to spend it. The entry
# format supports them the moment someone wires `test` to that job's artifact.
# Not listing them is a KNOWN COVERAGE GAP, named here rather than left to be
# discovered as a surprise.
#
# WHAT ALSO DOES NOT BELONG: a grep for a version string. See the v0.1.0 entry
# at the bottom, which was written the narrow way for a reason.

# CLASSES, added 2026-09-04 (TM-0394). The structural half of the 2026-09-03
# finding: the entries above check sentences somebody remembered to register,
# and an outside reader found three countable contradictions in an hour on a
# tree they were all green on. A class measures one kind of thing from the tree
# and then reads EVERY page in scope for a number attached to that noun, so a
# page nobody registered is still held to the count.
#
# FORMAT.
#
#   class:  a name for the report
#   match:  regex; the FIRST TOKEN of each match is read as the number, so it
#           must begin with the count. Non-numeric first tokens ("upstream
#           layers") are ignored; a class whose matches never yield a number
#           is refused, same as `states`.
#   test:   how the tree is measured, run from the repo root
#   expect: what it must print
#   scope:  OPTIONAL space-separated files/dirs/globs; default is DOC_SCOPE in
#           check-doc-claims.sh (docs/, the root pages, chart READMEs, the
#           executed-docs pages ... and NOT CHANGELOG.md, whose numbers are
#           dated history and must be allowed to disagree with today).
#
#   waive:  a page
#   match:  regex on the matched phrase, e.g. `three layers`
#   why:    the reason this number is not the class count ... a subset, a
#           distance, a measured figure with its own derivation
#
# A waiver that matches nothing fails (WAIVER UNUSED), so the waiver list rots
# no more quietly than the registry does. Prose only: fenced blocks, inline
# code, link targets and frontmatter are stripped before matching.
#
# WHAT IS NOT A CLASS, and why, so nobody adds it and then adds forty waivers:
#   namespaces     "nine", "seven", "five" and "four namespaces" are all true
#                  on different pages ... created, application-bearing,
#                  policy-owned, left behind by uninstall. Four senses, one noun.
#   Applications   "nine layer Applications" and "eleven Applications" (nine
#                  plus root plus the ApplicationSet's) are both right.
#   NetworkPolicies still not a class, but the reason changed on 2026-09-12.
#                  The old reason was that "33" needs a helm render. It does,
#                  and the render turned out to be affordable: three `page:`
#                  entries now run it, because three pages state the number and
#                  two of them had drifted to 32. Pinning each is enough while
#                  the set is three and enumerable. Make it a class the moment
#                  a fourth page states it, or the moment somebody has to guess
#                  which pages are covered.
#   consoles       "three shipped consoles" (behind SSO) and "the four
#                  consoles" (off-by-default port-forward) are different sets.
#   charts         "nine charts" (installable), "ten charts" (with the library
#                  chart) and "2 charts" (of a subset) are all true.
# ---------------------------------------------------------------------------
