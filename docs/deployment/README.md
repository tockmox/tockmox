# Deployment

These pages take you from "what do I need" to a running install, and then to the day you move it to a newer release. They are grouped by where you are, not numbered as one long sequence: most installs read **Before installation** and **Install**, and nothing else.

![The installation journey. Decide with the prerequisites page, then prepare a cluster on exactly one of two paths, a fresh k3s cluster or a cluster you already have. Install has four phases in order: generate your site repository, publish it, mint your credentials, apply the bootstrap. Argo CD then reconciles the nine layers in six waves. After the first sync you settle the install, then the first hour: trust the CA, bootstrap Authentik, make your own user, sign in, and send a first message once a model is named. Virtual machines, a registry of your own, and air-gap with time sync are side branches that apply only to some sites.](../diagrams/rendered/install-journey.svg)

**Which preparation path is yours.** Start at [prerequisites](prerequisites.md). It sends you to [a fresh cluster](fresh-install.md) if you are building one for Tockmox, or to [a cluster you already have](existing-cluster.md) if not. Both paths converge on [install](install.md), and the page after that is [sign in for the first time](../usage/getting-started.md).

**Special environments are not steps.** Virtual machines, a registry, air-gap and time synchronisation apply only to the sites that have them. A connected install does not need to read them first. [Upgrading](upgrade.md) and [air-gapped installs](airgap.md) are the two pages people come back to.
