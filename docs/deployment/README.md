# Deployment

These pages take you from "what do I need" to a running install, and then to the day you move it to a newer release. They are grouped by where you are, not numbered as one long sequence: most installs read **Before installation** and **Install**, and nothing else.

![The installation journey in six stages. Prepare: Kubernetes, Argo CD 2.6 or newer and sealed-secrets with your own key, on a fresh cluster or one you already have. Generate: the installer writes your site repository from your answers and applies nothing. Bootstrap: push it to git, mint your credentials, apply the root Application. Reconcile: Argo CD syncs the nine layers in six waves until each is healthy, then you settle the install. Configure: trust the CA, bootstrap Authentik, make your own user, name a model route. Use: sign in and send a first message. Virtual machines, a registry of your own, and no internet access are side branches only some sites need. This is a navigation overview, not the installation procedure.](../diagrams/rendered/install-journey.svg)

**Which preparation path is yours.** Start at [prerequisites](prerequisites.md). It sends you to [a fresh cluster](fresh-install.md) if you are building one for Tockmox, or to [a cluster you already have](existing-cluster.md) if not. Both paths converge on [install](install.md), and the page after that is [sign in for the first time](../usage/getting-started.md).

**Which shape is gated.** A release gate runs one shape: a single node on openSUSE MicroOS as a Harvester virtual machine. [Deployment shapes](deployment-shapes.md) is the table of what is gated, what is documented without a gate, and what is neither.

**Special environments are not steps.** Virtual machines, a registry, air-gap and time synchronisation apply only to the sites that have them. A connected install does not need to read them first. [Upgrading](upgrade.md) and [air-gapped installs](airgap.md) are the two pages people come back to.
