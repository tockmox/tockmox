Steps

Follow Upgrade to a new release (docs/deployment/upgrade.md). For a {{ kind if kind != "unknown" else "" }} upgrade it requires steps {{ steps|join(", ") }}. The commands below are the guide's, with your values set once at the top.

  1. Set your values once

    On your workstation

    export SITE_REPO=YOUR_SITE_REPO_PATH
export CURRENT_REVISION={{ cur_rev or "YOUR_CURRENT_REVISION" }}
export TARGET_REVISION={{ tgt_rev or "YOUR_TARGET_REVISION" }}
test -f "$SITE_REPO/bootstrap/root.yaml" && echo "SITE_REPO: $SITE_REPO"

  2. Write down what you are on now (step 0)

    kubectl -n {{ argocd_ns }} get applications -o \
  custom-columns='LAYER:.metadata.name,REVISION:.spec.sources[0].targetRevision,SYNC:.status.sync.status,HEALTH:.status.health.status'

  3. Read the release notes (step 1)

    Every version between {{ cur or "yours" }} and {{ tgt or "the target" }}. Breaking entries list the values you must add.

    4. {% if 2 in steps %}

  4. Back up, check customisations, diff the render (steps 2 to 4)

    The guide's steps 2, 3 and 4. A backup you have restored at least once is the only way back from a prune.

    5. {% endif %}

  5. Move the revision (step 5)

    In your site repository clone

    cd "$SITE_REPO"
sed -i.bak "s|targetRevision: $CURRENT_REVISION|targetRevision: $TARGET_REVISION|" \
  bootstrap/applications/*.yaml
rm -f bootstrap/applications/*.bak
git diff --stat
git commit -am "upgrade Tockmox to $TARGET_REVISION"
git push

    Leave lines reading targetRevision: main alone. Those track your own repository.

  6. Watch it land (steps 6 and 7)

    The status page shows each layer's revision, sync and health as Argo CD reconciles. Every layer should reach {{ tgt or "the new revision" }}, Synced and Healthy. Then open the consoles you use and sign in: that is the only check that proves sign-in still works.
