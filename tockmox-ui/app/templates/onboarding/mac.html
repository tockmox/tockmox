Two ways to set up this Mac. Enrolling hands the node's engines, firewall, memory ceiling and model store to a converger that pulls them from your own site repository, so a rebuilt Mac comes back the same. Managing it yourself is the list further down; it is complete on its own and is the right choice for a Mac you want to keep entirely by hand. A node you register without enrolling stays exactly as it is today.

Enroll for GitOps (recommended)

The only manual part is the console. After Setup Assistant the first thing you run on the Mac is one command, and everything after that is a commit to your site repository.

1. At the console, once

  1. Run Setup Assistant without an Apple Account: skip the sign-in. An Apple Account signed in on a server Mac can turn on features this setup turns off, and the readiness panel checks that none is signed in.
  2. Decide FileVault on purpose. The default is off, for a Mac in a rack that restarts on its own after a power cut; turning it on means someone unlocks it over SSH after every restart. The posture is a setting in the node's ai-node.yaml and the converger reports when the Mac disagrees with it.
  3. System Settings, General, Sharing: turn Remote Login on. Allow only the administrator account.
  4. In System Settings, set "Start up when power is connected" to Always (older macOS calls it "Start up automatically after a power failure"), so the Mac comes back by itself after a power cut.
  5. Install the current macOS update at the console, so the bootstrap starts from a supported release.

Run this from a checkout of the Tockmox repository at the toolkit release your nodes pin. It copies one script to the Mac and runs it there under sudo (ssh -t lets it ask for the administrator's password), and it prints the public halves of the deploy key and the age key it makes, for you to add to your site repository.

Manage it yourself

Every command runs on the Mac, in Terminal, as an administrator. The engine runs as a LaunchDaemon so it starts at boot without anyone signed in.

  1. Keep the Mac awake and recover from power loss

    sudo pmset -a sleep 0 disksleep 0 autorestart 1 womp 1 standby 0 autopoweroff 0

  2. Install Homebrew, if it is not there

    command -v brew || /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

  3. Let only the gateway in (pf), before anything listens

    macOS's packet filter, in its own anchor so a macOS update does not erase it. This comes before the engine so there is never a moment when it listens with nothing in front of it. {{ eng.note }}

    sudo tee /etc/pf.anchors/com.tockmox.models >/dev/null <<PF
table <gateway> const { {{ src|join(", ") }} }
pass in quick on lo0 proto tcp to any port {{ port }}
pass in quick proto tcp from <gateway> to any port {{ port }}
block return in quick proto tcp from any to any port {{ port }}
PF
grep -q com.tockmox.models /etc/pf.conf || printf 'anchor "com.tockmox.models"\nload anchor "com.tockmox.models" from "/etc/pf.anchors/com.tockmox.models"\n' | sudo tee -a /etc/pf.conf
sudo pfctl -E -f /etc/pf.conf

    A macOS update can rewrite /etc/pf.conf; re-run the last two lines after one, or manage them with your configuration tool.

  4. Install Ollama and run it as a LaunchDaemon on the network

    Use the Homebrew daemon, not the Ollama app: two copies fighting over port {{ port }} is a known trap.

    brew install ollama
sudo tee /Library/LaunchDaemons/com.tockmox.ollama.plist >/dev/null <<PLIST
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
  <key>Label</key><string>com.tockmox.ollama</string>
  <key>UserName</key><string>$(whoami)</string>
  <key>ProgramArguments</key><array><string>$(brew --prefix)/bin/ollama</string><string>serve</string></array>
  <key>EnvironmentVariables</key><dict>
    <key>OLLAMA_HOST</key><string>0.0.0.0:{{ port }}</string>
    <key>OLLAMA_KEEP_ALIVE</key><string>-1</string>
    <key>HOME</key><string>$HOME</string>
  </dict>
  <key>RunAtLoad</key><true/><key>KeepAlive</key><true/>
</dict></plist>
PLIST
sudo launchctl bootstrap system /Library/LaunchDaemons/com.tockmox.ollama.plist

  5. Install mlx-lm in its own environment

    brew install python@3.12

  10. Export metrics (recommended)

    node_exporter for the host and macmon for unified-memory use, GPU power and temperature. This page reads both through Prometheus; macmon is what lets it show memory pressure.

    brew install node_exporter macmon
brew services start node_exporter
macmon serve --port 9101 &

    Run macmon as a LaunchDaemon for real use, in the same shape as above. Add ports 9100 and 9101 to the pf anchor's gateway rule if Prometheus scrapes from the cluster.
