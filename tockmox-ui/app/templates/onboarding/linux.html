Every command runs on the node, as a user with sudo. Tested on Ubuntu 22.04 and 24.04.

  1. GPU driver

    NVIDIA hosts only, and not on DGX OS, which ships with it

    2. {% if engine == "ollama" %}

  2. Install Ollama

    curl -fsSL https://ollama.com/install.sh | sh

  3. Listen on the network, keep models loaded

    Ollama listens on 127.0.0.1 by default, so the gateway cannot reach it.

    sudo mkdir -p /etc/systemd/system/ollama.service.d
printf '[Service]\nEnvironment="OLLAMA_HOST=0.0.0.0:{{ port }}"\nEnvironment="OLLAMA_KEEP_ALIVE=24h"\n' \
  | sudo tee /etc/systemd/system/ollama.service.d/tockmox.conf
sudo systemctl daemon-reload
sudo systemctl restart ollama

  4. Let only the gateway in

    Ollama has no login of its own, so the firewall is what keeps everyone else out. If the node already runs a firewall, add the same rule there instead.

    sudo ufw allow OpenSSH
{% for c in src %}sudo ufw allow from {{ c }} to any port {{ port }} proto tcp
{% endfor %}sudo ufw deny {{ port }}/tcp
sudo ufw --force enable

  5. Pull a first model

    ollama pull {{ model or "MODEL" }}

    For example ollama pull qwen3:8b. Check the model fits: this page estimates it when you place it.

  6. Check it locally

    curl -s http://127.0.0.1:{{ port }}/api/version
curl -s http://127.0.0.1:{{ port }}/api/tags
    7. {% elif engine == "llama-server" %}

  7. Make a key the gateway will use

    openssl rand -hex 24 | sudo tee /etc/llama-server.key
sudo chmod 600 /etc/llama-server.key

    Store the same value as a Secret for the gateway (sealed, like your other secrets) and name it on the probe page; the change this page generates refers to the Secret by name and never contains the key.

  8. Run llama-server

    docker run -d --name llama-server --restart unless-stopped {% if ntype != "amd-strix-halo" %}--gpus all {% endif %}\
  -p {{ port }}:{{ port }} -v /etc/llama-server.key:/key:ro -v llama-models:/models \
  ghcr.io/ggml-org/llama.cpp:server-cuda \
  --host 0.0.0.0 --port {{ port }} --api-key-file /key -hf {{ model or "MODEL" }}

  11. Run {{ eng.name }}

    {% if engine == "vllm" %} 
    docker run -d --name vllm --restart unless-stopped --gpus all --ipc=host \
  -p {{ port }}:8000 -v hf-cache:/root/.cache/huggingface \
  vllm/vllm-openai:latest --model {{ model or "MODEL" }} --api-key "$(sudo cat /etc/vllm.key)"

    Pin the image to a release tag rather than latest once it works. On arm64 hosts (DGX Spark, Jetson) use an arm64 build.

    {% elif engine == "nim" %} 
    export NGC_API_KEY=YOUR_NGC_KEY
docker run -d --name nim --restart unless-stopped --gpus all --shm-size=16g \
  -e NGC_API_KEY -p {{ port }}:8000 -v nim-cache:/opt/nim/.cache \
  nvcr.io/nim/{{ model or "MODEL" }}:latest

    The NGC key pulls the container. NIM's own endpoint has no key in this shape, so the firewall step is the control; put a proxy in front if you need a token.

    {% elif engine == "sglang" %} 
    docker run -d --name sglang --restart unless-stopped --gpus all --ipc=host \
  -p {{ port }}:30000 -v hf-cache:/root/.cache/huggingface lmsysorg/sglang:latest \
  python3 -m sglang.launch_server --model-path {{ model or "MODEL" }} --host 0.0.0.0 --port 30000 --api-key "$(sudo cat /etc/sglang.key)"
    {% elif engine == "tgi" %} 
    docker run -d --name tgi --restart unless-stopped --gpus all --shm-size 1g \
  -p {{ port }}:80 -v tgi-data:/data ghcr.io/huggingface/text-generation-inference:latest --model-id {{ model or "MODEL" }}

    Follow the engine's own install guide. It must listen on the node's network address, on port {{ port }} unless you choose another.

    sudo apt-get install -y prometheus-node-exporter
